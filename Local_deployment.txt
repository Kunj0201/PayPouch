PayPouch: Local-First Development to AWS Deployment Plan
This roadmap details a two-stage process for building the PayPouch prototype. We will first create a complete, fully functional application that runs entirely on a local development machine. Once validated, we will deploy this application to a scalable, production-ready environment on AWS.

Stage 1: Local Development Environment
Goal: To build and test the entire application on your computer. This enables fast development cycles, easy debugging, and zero cloud costs during the initial build phase.

Step 1: Set Up a Local Server with Node.js/Express

What: Create a backend server that will run on your local machine to handle business logic.

How:

Install Node.js.

Create a new project folder and initialize it with npm init -y.

Install the Express framework: npm install express.

Create a server.js file. In this file, set up an Express app that listens on a local port (e.g., 3000).

Define API routes that mirror the functionality we need, for example:

POST /api/subscriptions (to create a subscription)

GET /api/subscriptions/:userId (to get subscriptions for a user)

Step 2: Set Up a Local Database with DynamoDB Local

What: Run a downloadable version of Amazon's DynamoDB database directly on your machine. It functions identically to the cloud version, making the future transition seamless.

Create a local dynamo db table : aws dynamodb create-table --table-name paypouch-subscriptions --attribute-definitions AttributeName=userId,AttributeType=S AttributeName=subscriptionId,AttributeType=S --key-schema AttributeName=userId,KeyType=HASH AttributeName=subscriptionId,KeyType=RANGE --provisioned-throughput ReadCapacityUnits=5,WriteCapacityUnits=5 --endpoint-url http://localhost:8000

How:

Follow the official AWS instructions to download and run DynamoDB Local. It's typically run with a single command in your terminal.

In your server.js file, use the AWS SDK to connect to your local DynamoDB instance by specifying the local endpoint (e.g., http://localhost:8000).

Write the logic within your Express routes to interact with this local database (create items, query items, etc.), just as the Lambda functions did in the previous plan.

Step 3: Connect the Frontend to the Local Backend

What: Modify the paypouch_webapp_v1 HTML file to communicate with your local server instead of being a standalone demo.

How:

Use the fetch() API in the frontend JavaScript.

When the user submits the "Add New Subscription" form, fetch() will send a POST request to http://localhost:3000/api/subscriptions with the subscription data.

When the dashboard loads, fetch() will send a GET request to http://localhost:3000/api/subscriptions/some-user-id to retrieve and display the user's data from the local database.

Outcome of Stage 1: You will have a fully functional prototype running entirely on your computer. You can sign up, add subscriptions, and see them persisted in your local database, all without touching the cloud.

Stage 2: AWS Deployment
Goal: To take the validated local application and deploy it to a scalable, secure, and publicly accessible AWS environment.

Step 4: Deploy the Database to Amazon DynamoDB

What: Create the production version of your database table in the AWS cloud.

How:

Log in to your AWS account.

Execute the AWS CLI command from the paypouch_phase1_backend artifact to create the paypouch-subscriptions table in the AWS cloud. This is a one-time setup step.

Step 5: "Lift and Shift" the Backend to a Container on AWS Fargate

What: The most direct way to move your Express server to AWS is to package it in a container and run it using AWS Fargate, a serverless compute engine for containers.

How:

Containerize: Install Docker on your machine. Create a Dockerfile in your backend project that specifies how to build a container image of your Node.js application.

Push to Registry: Build the Docker image and push it to Amazon ECR (Elastic Container Registry), which is a private storage gallery for your container images.

Deploy: Create an AWS Fargate service to run your container from ECR. Fargate will manage the underlying infrastructure for you. To expose your service to the internet, you will place an Application Load Balancer (ALB) in front of it, which provides a public URL.

Update Code: Modify the database connection code in your Express app to point to the live AWS DynamoDB service instead of the local instance.

Step 6: Deploy the Frontend to Amazon S3 & CloudFront

What: Host your static HTML, CSS, and JavaScript files on a globally distributed, fast, and secure platform.

How:

Create an Amazon S3 bucket and configure it for static website hosting.

Upload your index.html and any other assets to this bucket.

Create an Amazon CloudFront distribution that points to your S3 bucket. CloudFront is a Content Delivery Network (CDN) that will cache your website at edge locations around the world, making it load quickly for all users. It also provides a free SSL certificate for https://.

Final Update: Modify the fetch() URLs in your frontend JavaScript one last time to point to the public URL of your Application Load Balancer from Step 5.

Outcome of Stage 2: Your PayPouch prototype is now live on the internet. It is fully deployed on a scalable, secure, and cost-effective serverless architecture on AWS, ready for the next phases of development, such as user authentication and Stripe integration.
